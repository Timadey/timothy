# Site branding — design

**Date:** 2026-10-21
**Status:** Approved (approach A — one-time generation script, static assets committed)

## 1. Goals & scope

- Adopt the user-provided TT/π monogram logo (cream-on-black, with "TTADELEKE" wordmark) as the site's brand: browser-tab icons, header mark, admin mark, and a social-share default image.
- Replace the empty 0-byte `public/favicon.ico` with a real icon set (it exists today; browsers request it and get nothing).
- Give pages without their own cover image a default `og:image` (notes, search, ask, now, activity, about, collections) — posts/projects keep their own covers.
- Out of scope: dark mode, PWA manifest/install, logo editing beyond the crops described here, CMS-configurable branding, the "TTADELEKE" lockup in the header (site name stays "Timadey"), email-template branding (ask mail composer is separate, in-progress work).

## 2. Decisions

- **Approach A (user-approved):** commit the source PNG + a Pillow script; run once; commit generated static assets in `public/`. No runtime image generation.
- **Header treatment:** cropped monogram on its original black tile (no recolor, no baked rounding — CSS `rounded-lg` only) at 28px next to the existing bold "Timadey" text link. The TTADELEKE wordmark is trimmed out — illegible small, and the header brand is "Timadey".
- **Wordmark on the share card:** "Timadey", not TTADELEKE — consistent with the header choice; the card advertises the site.
- **Full branding pass:** favicon set (real multi-size `.ico` + 32/32 + 16/16 PNGs + 180 apple-touch-icon), public header mark, admin sidebar + login mark, og/twitter default card, `theme-color`.
- **theme-color = `#ffffff`** — matches the site's white header chrome, not the logo's black (the browser UI should blend with the page, not the mark).
- **Og fallback lives in `Seo::baseResult()`** so every component inherits it; admin returns the noindex base (og default present but irrelevant on noindex pages — harmless, keeps one code path).

## 3. Assets (all generated by `tools/generate-brand.py` from `resources/brand/logo-source.png`)

| Output | Spec |
|---|---|
| `resources/brand/logo-source.png` | Original 1254² file, committed (source lives in ~/Downloads otherwise — must be in-repo for regeneration) |
| `public/images/logo-mark.png` | ~512² monogram crop (wordmark excluded), original black bg |
| `public/favicon.ico` | Multi-size real ICO: 16/32/48 (Pillow `save(..., sizes=[(16,16),(32,32),(48,48)])`) |
| `public/favicon-32x32.png`, `public/favicon-16x16.png` | Per-size PNGs |
| `public/apple-touch-icon.png` | 180², black background (iOS rounds it natively) |
| `public/images/og-card.png` | 1200×630, black bg, monogram + "Timadey" (site wordmark rendered at generation time; macOS system font acceptable — generation is a one-time dev-machine task) |

Script requirements: deterministic outputs from a single source; crop box derived once (monogram region, wordmark excluded); clear error if source missing. Outputs are committed — CI/others don't run it.

## 4. Wiring

| Surface | File | Change |
|---|---|---|
| Head icons + theme-color | `resources/views/app.blade.php` | `<link rel="icon">` (ico + 32 png + 16 png), `<link rel="apple-touch-icon">`, `<meta name="theme-color" content="#ffffff">` — static tags in `<head>` (server-rendered; Inertia `Head` is client-only and wrong for this) |
| Public header | `resources/js/Layouts/PublicLayout.tsx` | Monogram `<img src="/images/logo-mark.png" alt="Timadey" width={28} height={28} className="rounded-lg">` before the "Timadey" text |
| Admin sidebar | `resources/js/Layouts/AdminLayout.tsx` | Same mark (smaller, 24px) next to brand text |
| Admin login | `resources/js/Pages/Admin/Login.tsx` | Same mark (28px) above/next to "Timadey Admin" |
| Og/twitter default | `app/Support/Seo.php` | `baseResult()` og gets `og:image => url('/images/og-card.png')`; `twitter:image` likewise; twitter card type already keys off image presence → becomes `summary_large_image` on those pages |

Error pages (`resources/views/errors/*.blade.php`) don't extend app.blade.php — leave them (out of scope; they inherit the browser default request for `/favicon.ico`, which now returns a real icon anyway).
